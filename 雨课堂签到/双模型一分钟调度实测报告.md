# Gemma + Qwen 双模型一分钟调度实测

## 调度时间线

1. 题目下发后立即启动 NVIDIA Gemma Thinking。
2. 3 秒仍未返回，启动 SiliconFlow Qwen Thinking 作为 hedge。
3. 第 25 秒仍没有合法答案，Thinking 结果不再阻塞答题。
4. 同时启动两个 Fast 路由；一致时直接采用，不一致时优先采用配置中的主路由。
5. 如果只有备用 Fast 路由成功而主路由排队，暂存备用答案，再重试一次主路由。
6. 20 秒前得到答案会等到第 20 秒提交；之后得到答案立即提交。
7. 以题目下发后 60 秒为硬上限，并为并发 HTTP 提交预留 6 秒。

## 真实图片题验证

测试目标是此前 SiliconFlow Fast 会误判的 C 语言平方和图片题：

- 正确答案：`B / 30`
- 两个 Thinking 请求：均在第 25 秒触发 cutoff
- SiliconFlow Fast：0.969 秒返回 `C`
- NVIDIA Fast：2.265 秒返回 `B`
- 双模型发生分歧，调度器按主路由选择 NVIDIA 的 `B`
- 调度函数在题目下发后约 27.281 秒给出正确答案
- 总尝试数：4

这次实测同时覆盖了 Thinking cutoff、NVIDIA 排队隔离、Fast 双路竞速、
答案分歧处理和主路由优先策略。

## 关键配置

```ini
AI_ROUTES=nvidia|google/gemma-4-31b-it;siliconflow|Qwen/Qwen3.5-27B
AI_THINKING_FIRST=1
AI_THINKING_TIMEOUT=25
AI_THINKING_HEDGE_DELAY=3
AI_THINKING_MAX_TOKENS=4096
AI_ROUTE_TIMEOUT=8
AI_ROUTE_CYCLES=2
AI_TOTAL_TIMEOUT=54

YKT_SUBMIT_PREFERRED_DELAY=20
YKT_AI_THINKING_CUTOFF=25
YKT_SUBMIT_HARD_LIMIT=60
YKT_SUBMIT_RESERVE=6
```
