# 雨课堂签到与答题系统最终全链路审计报告（v2.6.1）

## 1. 结论

当前源码中，既定功能已经形成完整闭环：

- 账号短信登录、腾讯滑块验证、验证成功后自动发送短信；
- 本地账号有效性复核、服务端定时巡检、失效状态同步；
- 多账号批量扫码签到、单课堂锚点、失败账号二次补签；
- 签到后保存 `lessonId + lessonToken + lessonContext`；
- 答题页独立展示课程、课堂、课件、题干、选项和实时倒计时；
- WebSocket 自动进入课堂、心跳、断线重连、探针账号切换；
- 手动作答和 AI 托管两种模式并存，二者账号互斥；
- 题型 0～4 的答案构造和批量提交；
- NVIDIA Gemma-4 与 SiliconFlow Qwen3.5 双路由、Thinking/Fast 切换；
- AI 结果校验、限时调度、失败账号二次提交、历史记录；
- 课堂/题目结束自动停止任务、清理本课堂凭证、等待下一课堂；
- PM2 三进程长期运行、三小时 Gemma-4 连通性检测。

代码级审计未发现尚未实现的占位函数、TODO 或断开的调用链。自动化回归全部通过。
但“生产课堂一定成功”仍需要真实课堂、真实账号、当前雨课堂服务端协议和真实 AI Key
联合验证；这些外部条件无法由离线源码审计替代。

## 3. 账号与验证码链路

1. 用户填写备注和手机号。
2. App 打开独立 `pages/captcha/captcha` 页面。
3. `captcha.html` 调起腾讯验证码；CSP 允许腾讯和动态 CDN HTTPS 脚本。
4. 成功结果通过 UniApp WebView bridge 回传。
5. bridge 未及时就绪时，每 500ms 重投成功结果。
6. 子页返回、物理返回、WebView 错误和 90 秒超时都能解除锁定。
7. App 收到合法 `ticket/randstr` 后 300ms 自动调用短信发送接口。
8. 登录成功后兼容 `res.cookies` 和 `Set-Cookie` 响应头。
9. 必须再通过 `/v/course_meta/user_info` 获取明确用户资料才写入账号库。
10. 同手机号重新登录且 Cookie 变化时，会清除旧课堂凭证，避免跨会话复用。

## 4. 有效性检测链路

- 前端不再因任意异常响应就判失效：
  - 明确 401/403、登录页、认证错误码或认证失效消息才判定 `expired`；
  - WAF、网关 HTML、超时和未知结构保持 `unknown`。
- 服务端每 6 小时并发复核全部账号。
- 有效性五个字段按时间戳作为一个原子单元合并：
  - `expired`
  - `validityState`
  - `validitySource`
  - `validityCheckedAt`
  - `validityFailureCount`
- 客户端的 `unknown` 结果不能覆盖服务端已有的明确 `expired`。
- 新的明确 `valid/expired` 结果可以按时间戳更新旧状态。

## 5. 批量签到与补签链路

1. 扫描链接只接受 `yuketang.cn` 或其子域，并限制为签到路径。
2. 新批次先串行寻找第一个成功解析 `lessonId` 的账号。
3. 第一个有效 `lessonId` 成为整个批次的课堂锚点。
4. 其余账号以 16 并发执行 scan 和 checkin。
5. 任意账号返回其他 `lessonId` 时会被隔离，不能改写全局课堂。
6. 每个成功账号保存独立的 `lessonToken`。
7. 失败账号进入补签列表；补签已存在锚点时必须继续锁定原课堂。
8. 如果首轮所有账号都未能建立锚点，补签允许使用新二维码建立课堂，避免被旧
   `currentLessonId` 错误阻塞。
9. 摄像头错误、关闭按钮和物理返回都会释放原生扫码组件。

动态二维码生成不属于当前实现。现有逆向证据只确认客户端提交教师下发的动态 URL，
没有发现可离线生成并绕过服务端校验的完整算法；当前功能依赖扫描有效课堂二维码。

## 6. 课堂、WebSocket 与课件链路

- 签到后自动绑定课堂并启动实时监控。
- 课堂详情会合并 basic-info 和 detail 的多个响应结构，展示课程、课堂和教师信息。
- 优先使用课堂响应中的官方 `*.yuketang.cn` `wssUrl`，否则回退配置的 `/wsapp/`。
- hello 包含 `userid`、`role=student`、`auth=lessonToken` 和 `lessonid`。
- 每 15 秒发送 `detectlesson`，前端同时保守检测 90 秒静默连接。
- hello 鉴权失败会切换其他账号；全部失败 15/20 秒后清空失败列表重试。
- 已支持的题目事件：
  - `unlockproblem` / `unlock_problem`
  - `sendsproblem` / `sendproblem`
  - `sproblemshown` / `problemshown`
  - `probleminfo`
  - `extendtime`
  - `problemfinished` / `finishproblem`
- 已支持课件事件：
  - `showpresentation`
  - `slidenav`
  - `presentationupdated`
- 已支持课堂结束别名：
  - `lessonfinished`
  - `finishlesson`
  - `endlesson`
  - `lessonend`
- 支持事件字段位于顶层或嵌套 `data`。
- 重连 hello 中的 `unlockedproblem` 可以恢复当前未关闭题目。
- `probleminfo` 会补齐题干和选项，但不会形成自请求循环。
- 课件解析兼容嵌套 `data`、`presentation`、`presentationData`、顶层 problems、
  slide、shape 图片和相对 URL。

## 7. 手动批量答题

- 答题账号区域默认折叠。
- 就绪的非 AI 账号默认全选。
- AI 托管账号自动排除在手动选择之外，避免同一账号重复交卷。
- 题型映射：
  - 0：单选，`result: ["A"]`
  - 1：多选，去重并排序
  - 2：投票，受 `pollingCount` 最大选择数限制
  - 3：填空，必须填写所有空
  - 4：简答，`{content,pics:[],videos:[]}`
- 提交携带 Cookie、CSRF、设备头、`lessonToken` 和精确 `problemId`。
- 超出 JavaScript 安全整数范围的数字 ID 使用原始 JSON 数字文本，避免精度损失。
- 单账号失败不阻断其他账号；网络/5xx 自动重试一次。
- 认证失败只清理对应账号、本课堂的 `lessonToken`。

## 8. AI 自动答题

1. 只处理 `ai_mode=true`、未失效、Cookie/UID/lessonToken 完整且属于当前课堂的账号。
2. 新题先补齐课件、题干、选项、图片、填空数和投票最大选择数。
3. 立即启动主路由 Thinking。
4. 3 秒未返回时启动另一供应商 Thinking 对冲。
5. 25 秒截止 Thinking，之后进入双供应商 Fast。
6. Fast 结果一致则直接使用；不一致时优先主路由。
7. 备用模型先成功时保留答案并再尝试一次主路由。
8. AI 答案必须通过题型和选项合法性校验。
9. 正常情况下不早于题目下发后 20 秒提交。
10. 教师截止时间更短时自动提前；全任务硬上限 60 秒，并预留提交时间。
11. 16 并发提交；失败账号在剩余时间内再进行一轮提交。
12. 历史记录保存模型、供应商、尝试链、耗时、成功账号和课程信息。

## 9. 课堂结束与下一课堂

收到明确课堂结束信号后：

- 停止前端 WebSocket、心跳、重连、倒计时和课件重试；
- 取消服务端该课堂的 AI 题目任务；
- 只清理匹配 `groupKey + lessonId` 的课堂凭证；
- 不影响其他课堂或其他租户；
- 页面进入“课堂已结束”状态；
- 下次签到新课堂时重新绑定上下文、重建 WebSocket、重置题目和课件。

## 10. 云同步与租户隔离

- 租户 Key 只保存 SHA-256，不在服务器明文 Key 库中保存。
- 管理员口令不能被创建成普通租户 Key。
- 更新/删除同时提交 `key_id` 和 Key 时必须指向同一记录，不能误删两个租户。
- 每个账号按 `tenant_id + phone/uid/id` 隔离。
- 手机端“移除账号”严格限定为本地操作，不会向服务器发送删除 tombstone；
  云端账号仍可通过“从云端拉取”恢复。
- App 启动和切换密钥时会清理 v2.6.0 遗留的待删除队列，防止升级后误删云端账号。
- 服务端默认 `YKT_ALLOW_REMOTE_ACCOUNT_DELETE=0`。即使旧版 App 仍发送 tombstone，
  API 也只记录并忽略，不会删除数据库账号。
- `lessonId/lessonToken/lessonContext` 按 `lessonCredentialUpdatedAt` 原子合并。
- 旧客户端或旧页面不能用空值抹掉较新的课堂凭证。
- 删除租户 Key 时同时清理账号、AI 历史和题目运行状态。
- JSON 数据跨线程、跨进程加锁并原子替换，保留上一版本备份。
